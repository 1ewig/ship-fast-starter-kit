## Why This Stack?

This is a modern, scalable stack for seamless authentication, efficient database management, and robust backend services combining Next.js 16, Better Auth, Drizzle ORM, and Supabase.

In September 2025, the Auth.js (formerly NextAuth.js) development team joined Better Auth. Auth.js will continue to receive security patches and critical updates, but Better Auth is now recommended for new projects.

Better Auth comes with built-in support for OAuth 2.0 and OpenID Connect, allowing you to authenticate users via popular OAuth providers like Google, Facebook, GitHub, and more. If your desired provider isn't directly supported, you can use the Generic OAuth Plugin for custom integrations.

Database joins in the Drizzle adapter are useful when Better Auth needs to fetch related data from multiple tables in a single query. Endpoints like `/get-session`, `/get-full-organization`, and many others benefit greatly from this feature, seeing upwards of 2x to 3x performance improvements depending on database latency. The Drizzle adapter supports joins out of the box since version 1.4.0.

Key reasons to choose this stack:
- **Better Auth** — Framework-agnostic, TypeScript-first, security-hardened, plugin-based
- **Drizzle ORM** — Elegant and type-safe database management with zero runtime overhead
- **Supabase** — Robust backend services for your application backed by PostgreSQL

## Supabase & Database Setup

### 1. Create a Supabase Project

1. Go to [supabase.com](https://supabase.com) → **New Project**
2. Choose a region, set a strong DB password
3. Go to **Settings → Database → Connection String** — copy the **URI** (Transaction Pooler for serverless, Direct for migrations)

### 2. Supabase Connection Modes

| Mode | Use Case | Pool |
|------|----------|------|
| **Transaction Pooler** | Serverless functions, API routes | Port `6543` |
| **Session Pooler** | Long-lived connections | Port `5432` |
| **Direct Connection** | Migrations, `drizzle-kit push` | Port `5432` |

```bash
# .env.local
# Transaction Pooler (for runtime queries)
DATABASE_URL=postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres?pgmode=transaction

# Direct (for drizzle-kit migrations only)
DATABASE_URL_DIRECT=postgresql://postgres.[ref]:[password]@db.[ref].supabase.co:5432/postgres
```

> ⚠️ Keep your `SUPABASE_DATABASE_URL` secure and never commit it to your repository.

## Drizzle ORM Schema

The kit uses Drizzle ORM with the PostgreSQL adapter. Auth tables — users, sessions, accounts, and verifications — are defined in the Drizzle schema. Better Auth manages these tables automatically.

Better Auth provides a `generate` command to generate the schema required. The `generate` command creates the schema required by Better Auth. If you're using a database adapter like Prisma or Drizzle, this command will generate the right schema for your ORM.

Run the generator first, then extend it:

```bash
npx auth@latest generate --output src/db/schema/auth-schema.ts
```

Now create the full schema manually for complete control:

```ts
// src/db/schema/auth-schema.ts
import {
  pgTable,
  text,
  timestamp,
  boolean,
  integer,
  uuid,
  index,
} from "drizzle-orm/pg-core";
import { relations } from "drizzle-orm";

// ─── Users ───────────────────────────────────────────────────────────────────
export const user = pgTable(
  "user",
  {
    id: text("id").primaryKey(),
    name: text("name").notNull(),
    email: text("email").notNull().unique(),
    emailVerified: boolean("email_verified").notNull().default(false),
    image: text("image"),
    role: text("role").notNull().default("user"),       // user | admin | moderator
    banned: boolean("banned").notNull().default(false),
    banReason: text("ban_reason"),
    banExpires: timestamp("ban_expires"),
    twoFactorEnabled: boolean("two_factor_enabled").notNull().default(false),
    createdAt: timestamp("created_at").notNull().defaultNow(),
    updatedAt: timestamp("updated_at").notNull().defaultNow(),
  },
  (t) => [index("user_email_idx").on(t.email)]
);

// ─── Sessions ────────────────────────────────────────────────────────────────
export const session = pgTable(
  "session",
  {
    id: text("id").primaryKey(),
    expiresAt: timestamp("expires_at").notNull(),
    token: text("token").notNull().unique(),
    ipAddress: text("ip_address"),
    userAgent: text("user_agent"),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    impersonatedBy: text("impersonated_by"),
    createdAt: timestamp("created_at").notNull().defaultNow(),
    updatedAt: timestamp("updated_at").notNull().defaultNow(),
  },
  (t) => [
    index("session_token_idx").on(t.token),
    index("session_user_idx").on(t.userId),
  ]
);

// ─── Accounts (Linked Social Providers) ──────────────────────────────────────
export const account = pgTable(
  "account",
  {
    id: text("id").primaryKey(),
    accountId: text("account_id").notNull(),
    providerId: text("provider_id").notNull(),           // google | github | credential
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    accessToken: text("access_token"),
    refreshToken: text("refresh_token"),
    idToken: text("id_token"),
    accessTokenExpiresAt: timestamp("access_token_expires_at"),
    refreshTokenExpiresAt: timestamp("refresh_token_expires_at"),
    scope: text("scope"),
    password: text("password"),
    createdAt: timestamp("created_at").notNull().defaultNow(),
    updatedAt: timestamp("updated_at").notNull().defaultNow(),
  },
  (t) => [
    index("account_user_idx").on(t.userId),
    index("account_provider_idx").on(t.providerId, t.accountId),
  ]
);

// ─── Email Verifications ──────────────────────────────────────────────────────
export const verification = pgTable("verification", {
  id: text("id").primaryKey(),
  identifier: text("identifier").notNull(),
  value: text("value").notNull(),
  expiresAt: timestamp("expires_at").notNull(),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});

// ─── Two Factor ───────────────────────────────────────────────────────────────
export const twoFactor = pgTable("two_factor", {
  id: text("id").primaryKey(),
  secret: text("secret").notNull(),
  backupCodes: text("backup_codes").notNull(),
  userId: text("user_id")
    .notNull()
    .references(() => user.id, { onDelete: "cascade" }),
});

// ─── Rate Limits ──────────────────────────────────────────────────────────────
export const rateLimit = pgTable("rate_limit", {
  id: text("id").primaryKey(),
  key: text("key"),
  count: integer("count"),
  lastRequest: integer("last_request"),
});

// ─── Drizzle Relations ────────────────────────────────────────────────────────
export const userRelations = relations(user, ({ many }) => ({
  sessions: many(session),
  accounts: many(account),
}));

export const sessionRelations = relations(session, ({ one }) => ({
  user: one(user, { fields: [session.userId], references: [user.id] }),
}));

export const accountRelations = relations(account, ({ one }) => ({
  user: one(user, { fields: [account.userId], references: [user.id] }),
}));
```

> 💡 To enable database joins, set the `experimental.joins` option to `true` in your auth configuration. If you do not see any relations in your Drizzle schema, you can manually add them using the `relation` drizzle-orm function or run `npx auth@latest generate` to generate a new Drizzle schema with the relations.

## Drizzle Config & DB Client

### `drizzle.config.ts`

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  out: "./drizzle",
  schema: "./src/db/schema/auth-schema.ts",
  dialect: "postgresql",
  dbCredentials: {
    // Use DIRECT URL for migrations — not the pooler
    url: process.env.DATABASE_URL_DIRECT!,
  },
  verbose: true,
  strict: true,
});
```

### `src/db/index.ts` — The Drizzle Client

```ts
// src/db/index.ts
import { drizzle } from "drizzle-orm/postgres-js";
import postgres from "postgres";
import * as schema from "./schema/auth-schema";

// Prevent multiple instances in development (Next.js hot reload)
declare global {
  var _db: ReturnType<typeof drizzle> | undefined;
}

function createDb() {
  const client = postgres(process.env.DATABASE_URL!, {
    max: process.env.NODE_ENV === "production" ? 10 : 1,
    idle_timeout: 20,
    connect_timeout: 10,
    prepare: false,                 // Required for Supabase Transaction Pooler
  });

  return drizzle(client, {
    schema,
    logger: process.env.NODE_ENV === "development",
  });
}

export const db = global._db ?? createDb();

if (process.env.NODE_ENV !== "production") {
  global._db = db;
}
```

> ⚠️ **Supabase Pooler Note:** Set `prepare: false` when using Supabase's transaction pooler (port 6543). Prepared statements are not supported in transaction pooling mode and will cause connection errors.

## Better Auth Server Config

```ts
// src/lib/auth.ts
import { betterAuth } from "better-auth";
import { drizzleAdapter } from "better-auth/adapters/drizzle";
import { db } from "@/db";
import * as schema from "@/db/schema/auth-schema";
import {
  twoFactor,
  multiSession,
  emailOTP,
  passkey,
  admin,
  bearer,
  openAPI,
} from "better-auth/plugins";
import { resend } from "@/lib/email"; // your Resend client

export const auth = betterAuth({
  // ─── App URL ────────────────────────────────────────────────────────────────
  baseURL: process.env.NEXT_PUBLIC_APP_URL!,
  secret: process.env.BETTER_AUTH_SECRET!,

  // ─── Database (Drizzle + Supabase) ─────────────────────────────────────────
  database: drizzleAdapter(db, {
    provider: "pg",
    schema: {
      user: schema.user,
      session: schema.session,
      account: schema.account,
      verification: schema.verification,
      twoFactor: schema.twoFactor,
      rateLimit: schema.rateLimit,
    },
  }),

  // ─── Enable Joins for performance ──────────────────────────────────────────
  experimental: {
    joins: true,                      // 2–3x perf improvement on session fetches
  },

  // ─── Email + Password ────────────────────────────────────────────────────
  emailAndPassword: {
    enabled: true,
    requireEmailVerification: true,   // Block unverified logins entirely
    minPasswordLength: 10,
    maxPasswordLength: 128,
    autoSignIn: false,                // Force explicit sign-in after registration
    password: {
      hash: async (password) => {
        // bcrypt with cost factor 12
        const bcrypt = await import("bcryptjs");
        return bcrypt.hash(password, 12);
      },
      verify: async ({ hash, password }) => {
        const bcrypt = await import("bcryptjs");
        return bcrypt.compare(password, hash);
      },
    },
    sendResetPassword: async ({ user, url }) => {
      await resend.emails.send({
        from: "noreply@yourapp.com",
        to: user.email,
        subject: "Reset Your Password",
        html: `<a href="${url}">Reset Password</a>`,
      });
    },
  },

  // ─── Email Verification ──────────────────────────────────────────────────
  emailVerification: {
    sendOnSignUp: true,
    autoSignInAfterVerification: true,
    sendVerificationEmail: async ({ user, url }) => {
      await resend.emails.send({
        from: "noreply@yourapp.com",
        to: user.email,
        subject: "Verify your email",
        html: `<p>Hi ${user.name}, click <a href="${url}">here</a> to verify your email.</p>`,
      });
    },
  },

  // ─── Social Providers ────────────────────────────────────────────────────
  socialProviders: {
    google: {
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
      scope: ["openid", "email", "profile"],
    },
    github: {
      clientId: process.env.GITHUB_CLIENT_ID!,
      clientSecret: process.env.GITHUB_CLIENT_SECRET!,
    },
    discord: {
      clientId: process.env.DISCORD_CLIENT_ID!,
      clientSecret: process.env.DISCORD_CLIENT_SECRET!,
    },
    twitter: {
      clientId: process.env.TWITTER_CLIENT_ID!,
      clientSecret: process.env.TWITTER_CLIENT_SECRET!,
    },
  },

  // ─── Account Linking ─────────────────────────────────────────────────────
  account: {
    accountLinking: {
      enabled: true,
      // Providers auto-linked when email matches (no manual confirmation needed)
      // Can be a static array or async function for dynamic resolution
      trustedProviders: ["google", "github"],
      // Prevent cross-email linking (security best practice)
      allowDifferentEmails: false,
      // Allow users to remove all linked accounts (disabled = must keep at least one)
      allowUnlinkingAll: false,
    },
  },

  // ─── Session ────────────────────────────────────────────────────────────
  session: {
    expiresIn: 60 * 60 * 24 * 7,       // 7 days
    updateAge: 60 * 60 * 24,           // Refresh session if older than 1 day
    cookieCache: {
      enabled: true,
      maxAge: 5 * 60,                  // 5-minute client-side session cache
    },
  },

  // ─── Rate Limiting ───────────────────────────────────────────────────────
  rateLimit: {
    enabled: true,
    window: 10,
    max: 100,
    storage: "database",              // persisted in Supabase via Drizzle
    modelName: "rateLimit",
    customRules: {
      "/sign-in/email":               { window: 10,  max: 3 },
      "/sign-up/email":               { window: 10,  max: 3 },
      "/forget-password":             { window: 60,  max: 3 },
      "/sign-in/magic-link":          { window: 60,  max: 3 },
      "/email-otp/send-verification-otp": { window: 60, max: 3 },
      "/two-factor/verify-totp":      { window: 10,  max: 5 },
      "/link-social-account":         { window: 30,  max: 5 },
    },
  },

  // ─── Trusted Origins (CSRF) ──────────────────────────────────────────────
  trustedOrigins: [
    process.env.NEXT_PUBLIC_APP_URL!,
    "https://your-production-domain.com",
  ],

  // ─── Advanced Security ───────────────────────────────────────────────────
  advanced: {
    useSecureCookies: process.env.NODE_ENV === "production",
    generateId: () => crypto.randomUUID(),
    defaultCookieAttributes: {
      sameSite: "lax",
      httpOnly: true,
      secure: process.env.NODE_ENV === "production",
    },
    crossSubDomainCookies: { enabled: false },
    // Verification tokens stored as hashed values
  },

  // ─── Verification Storage ────────────────────────────────────────────────
  verification: {
    disableCleanup: false,
    storeIdentifier: "hashed",        // Never store plain tokens
  },

  // ─── Plugins ────────────────────────────────────────────────────────────
  plugins: [
    // Two-Factor Authentication
    twoFactor({
      issuer: "YourApp",
      totpOptions: { digits: 6, period: 30 },
      skipVerificationOnEnable: false,
    }),

    // Multi-device session support
    multiSession({
      maximumSessions: 5,
      sessionManagement: {
        revokeOtherSessions: false,
      },
    }),

    // Email OTP
    emailOTP({
      async sendVerificationOTP({ email, otp, type }) {
        await resend.emails.send({
          from: "noreply@yourapp.com",
          to: email,
          subject: type === "sign-in" ? "Your Sign-In Code" : "Verify Your Email",
          html: `<p>Your code is: <strong>${otp}</strong>. Expires in 10 minutes.</p>`,
        });
      },
      otpLength: 6,
      expiresIn: 600, // 10 minutes
    }),

    // WebAuthn Passkeys
    passkey({
      rpName: "YourApp",
      rpID: process.env.NEXT_PUBLIC_DOMAIN!,
      origin: process.env.NEXT_PUBLIC_APP_URL!,
    }),

    // Admin panel support
    admin({
      defaultRole: "user",
      adminRoles: ["admin"],
    }),

    // Bearer token for API access
    bearer(),

    // OpenAPI docs (disable in production if not needed)
    ...(process.env.NODE_ENV === "development" ? [openAPI()] : []),
  ],
});

// Type exports
export type Session = typeof auth.$Infer.Session;
export type User = typeof auth.$Infer.Session.user;
```

> 🔐 **Account Linking note from Better Auth docs:** Account linking is enabled by default and lets users associate multiple authentication methods with a single account. With Better Auth, users can connect additional social sign-ons or OAuth providers to their existing accounts if the provider confirms the user's email as verified.

> ⚠️ If account linking is disabled, no accounts can be linked, regardless of the provider or email verification status.

> 🔒 **Email safety:** The synced fields are the same ones persisted on sign-up. The user's email and `emailVerified` are never changed on a link, so linking a provider can't rebind the account's identity.

## Data Access Layer (DAL)

The DAL is the single source of truth for session verification. It must be called inside every Server Component, Layout, and Server Action that touches protected data.

```ts
// src/lib/dal.ts
import { cache } from "react";
import { redirect } from "next/navigation";
import { headers } from "next/headers";
import { auth } from "@/lib/auth";

/**
 * React `cache()` deduplicates calls across a single request tree.
 * Calling verifySession() 10 times in one render = only 1 DB query.
 */
export const verifySession = cache(async () => {
  try {
    const session = await auth.api.getSession({
      headers: await headers(),
    });
    return session ?? null;
  } catch {
    return null;
  }
});

/**
 * Use in protected pages and layouts.
 * Redirects unauthenticated users to /sign-in.
 */
export const requireAuth = cache(async () => {
  const session = await verifySession();
  if (!session) {
    redirect("/sign-in");
  }
  return session;
});

/**
 * Use in admin-only pages.
 * Redirects non-admins to /dashboard.
 */
export const requireAdmin = cache(async () => {
  const session = await requireAuth();
  if (session.user.role !== "admin") {
    redirect("/dashboard");
  }
  return session;
});

/**
 * Use when you need user data but the route is publicly accessible.
 * Never throws — returns null if unauthenticated.
 */
export const getOptionalSession = cache(async () => {
  return await verifySession();
});
```

## Multi-Method Sign-In Page

```tsx
// src/app/(auth)/sign-in/page.tsx
"use client";

import { authClient } from "@/lib/auth-client";
import { useState, useTransition } from "react";
import { useRouter, useSearchParams } from "next/navigation";
import { resolveAuthError } from "@/lib/auth-errors";

export default function SignInPage() {
  const router = useRouter();
  const searchParams = useSearchParams();
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");
  const [otp, setOtp] = useState("");
  const [otpSent, setOtpSent] = useState(false);
  const [error, setError] = useState<string | null>(
    searchParams.get("error")
      ? "An error occurred during sign-in. Please try again."
      : null
  );
  const [success, setSuccess] = useState<string | null>(null);
  const [isPending, startTransition] = useTransition();

  // ── Email + Password ───────────────────────────────────────────────────────
  const handleCredentialSignIn = async (e: React.FormEvent) => {
    e.preventDefault();
    setError(null);

    startTransition(async () => {
      const { error } = await authClient.signIn.email({
        email: email.trim().toLowerCase(),
        password,
        callbackURL: "/dashboard",
        rememberMe: true,
        fetchOptions: {
          onSuccess: () => router.push("/dashboard"),
          onError: (ctx) => setError(resolveAuthError(ctx.error).message),
        },
      });

      if (error) setError(resolveAuthError(error).message);
    });
  };

  // ── Social Sign In ─────────────────────────────────────────────────────────
  const handleSocial = (provider: "google" | "github" | "discord" | "twitter") => {
    startTransition(async () => {
      const { error } = await authClient.signIn.social({
        provider,
        callbackURL: "/dashboard",
        errorCallbackURL: `/sign-in?error=${provider}_failed`,
      });
      if (error) setError(resolveAuthError(error).message);
    });
  };

  // ── Magic Link ─────────────────────────────────────────────────────────────
  const handleMagicLink = async () => {
    if (!email) { setError("Enter your email address first."); return; }
    setError(null);

    startTransition(async () => {
      const { error } = await authClient.signIn.magicLink({
        email: email.trim().toLowerCase(),
        callbackURL: "/dashboard",
      });

      if (error) setError(resolveAuthError(error).message);
      else setSuccess("Magic link sent! Check your email inbox.");
    });
  };

  // ── Email OTP ──────────────────────────────────────────────────────────────
  const handleSendOTP = async () => {
    if (!email) { setError("Enter your email address first."); return; }
    setError(null);

    startTransition(async () => {
      const { error } = await authClient.emailOtp.sendVerificationOtp({
        email: email.trim().toLowerCase(),
        type: "sign-in",
      });

      if (error) setError(resolveAuthError(error).message);
      else setOtpSent(true);
    });
  };

  const handleVerifyOTP = async () => {
    setError(null);

    startTransition(async () => {
      const { error } = await authClient.signIn.emailOtp({
        email: email.trim().toLowerCase(),
        otp,
        callbackURL: "/dashboard",
      });

      if (error) setError(resolveAuthError(error).message);
    });
  };

  // ── Passkey ────────────────────────────────────────────────────────────────
  const handlePasskey = async () => {
    setError(null);
    startTransition(async () => {
      const { error } = await authClient.signIn.passkey({
        fetchOptions: {
          onSuccess: () => router.push("/dashboard"),
        },
      });
      if (error) setError(resolveAuthError(error).message);
    });
  };

  return (
    <div className="max-w-md mx-auto p-8 space-y-6">
      <h1 className="text-2xl font-bold">Sign In</h1>

      {error && (
        <div role="alert" className="p-4 bg-red-50 text-red-700 rounded-lg border border-red-200">
          {error}
        </div>
      )}
      {success && (
        <div role="status" className="p-4 bg-green-50 text-green-700 rounded-lg border border-green-200">
          {success}
        </div>
      )}

      {/* Email + Password */}
      <form onSubmit={handleCredentialSignIn} className="space-y-4">
        <input
          type="email"
          placeholder="Email address"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          required
          autoComplete="email"
          className="w-full border rounded-lg px-4 py-2"
        />
        <input
          type="password"
          placeholder="Password (10+ characters)"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
          required
          autoComplete="current-password"
          minLength={10}
          className="w-full border rounded-lg px-4 py-2"
        />
        <button
          type="submit"
          disabled={isPending}
          className="w-full bg-black text-white py-2 rounded-lg disabled:opacity-50"
        >
          {isPending ? "Signing in..." : "Sign in with Email"}
        </button>
      </form>

      <div className="flex items-center gap-2">
        <hr className="flex-1" />
        <span className="text-sm text-gray-500">or</span>
        <hr className="flex-1" />
      </div>

      {/* Social Providers */}
      <div className="space-y-2">
        {(["google", "github", "discord", "twitter"] as const).map((provider) => (
          <button
            key={provider}
            onClick={() => handleSocial(provider)}
            disabled={isPending}
            className="w-full border rounded-lg py-2 flex items-center justify-center gap-2 hover:bg-gray-50 disabled:opacity-50 capitalize"
          >
            Continue with {provider}
          </button>
        ))}
      </div>

      {/* Magic Link */}
      <button
        onClick={handleMagicLink}
        disabled={isPending || !email}
        className="w-full border rounded-lg py-2 hover:bg-gray-50 disabled:opacity-50"
      >
        ✉️ Send Magic Link
      </button>

      {/* Email OTP */}
      {!otpSent ? (
        <button
          onClick={handleSendOTP}
          disabled={isPending || !email}
          className="w-full border rounded-lg py-2 hover:bg-gray-50 disabled:opacity-50"
        >
          🔢 Sign in with OTP Code
        </button>
      ) : (
        <div className="space-y-2">
          <input
            type="text"
            placeholder="Enter 6-digit OTP"
            value={otp}
            onChange={(e) => setOtp(e.target.value)}
            maxLength={6}
            inputMode="numeric"
            className="w-full border rounded-lg px-4 py-2"
          />
          <button
            onClick={handleVerifyOTP}

            Verify OTP

        disabled={isPending}
        className="w-full border rounded-lg py-2 hover:bg-gray-50 disabled:opacity-50"
```

## Account Linking & Delinking

Use the `linkSocial` method on the client to link a social provider to the user's account.

You can unlink a user account by providing a `providerId`.

To link a credential-based account (e.g., email and password), users can initiate a "forgot password" flow, or you can call the `setPassword` method on the server. `setPassword` can't be called from the client for security reasons.

**Known limitation to guard against:** Better Auth does not support treating multiple email addresses as belonging to the same underlying user unless the user manually links them through `allowDifferentEmails` in the `accountLinking` configuration. This approach has limitations: it only works after the user signs in, meaning account fragmentation still occurs first and must be corrected manually. It also only supports linking social provider accounts, not cases where users sign in using different email addresses directly via Magic Link, password login, or different email addresses used with multiple providers.

**Important security consideration:** When implementing a strict OWASP-compliant security flow, if a user tries to sign in with a social provider but already has a password account with the same email, you should block the automatic login/merge. The user should be prompted to log in with their password first. Once authenticated, they should be able to explicitly link that provider from their settings page using `authClient.linkSocial`.

```tsx
// src/components/account-manager.tsx
"use client";

import { authClient } from "@/lib/auth-client";
import { useState, useTransition } from "react";
import { resolveAuthError } from "@/lib/auth-errors";

const PROVIDERS = [
  { id: "google",  label: "Google",  icon: "🔵" },
  { id: "github",  label: "GitHub",  icon: "⚫" },
  { id: "discord", label: "Discord", icon: "🟣" },
  { id: "twitter", label: "Twitter", icon: "🐦" },
] as const;

type Provider = typeof PROVIDERS[number]["id"];

interface Props {
  user: { name: string; email: string };
  linkedAccounts: Array<{ provider: string; providerId?: string }>;
}

export function AccountManager({ user, linkedAccounts }: Props) {
  const [error, setError] = useState<string | null>(null);
  const [successMsg, setSuccessMsg] = useState<string | null>(null);
  const [isPending, startTransition] = useTransition();

  const linkedProviders = linkedAccounts.map((a) => a.provider);
  const hasPassword = linkedAccounts.some((a) => a.provider === "credential");

  const clearMessages = () => { setError(null); setSuccessMsg(null); };

  // ── LINK ─────────────────────────────────────────────────────────────────
  const handleLink = (provider: Provider) => {
    clearMessages();
    startTransition(async () => {
      const { error } = await authClient.linkSocialAccount({
        provider,
        callbackURL: "/account?linked=true",
        errorCallbackURL: `/account?error=link_failed&provider=${provider}`,
      });

      if (error) {
        const resolved = resolveAuthError(error);
        setError(resolved.message);

        // Handle the specific case where auto-linking conflicts with OWASP strict mode
        if (error.code === "SOCIAL_ACCOUNT_ALREADY_LINKED") {
          setError("This social account is already connected to a different user.");
        }
      } else {
        setSuccessMsg(`${provider} account linked successfully.`);
      }
    });
  };

  // ── DELINK ────────────────────────────────────────────────────────────────
  const handleDelink = (provider: Provider) => {
    clearMessages();

    // Safety check: ensure user won't lose their only sign-in method
    const remainingProviders = linkedProviders.filter((p) => p !== provider);
    if (!hasPassword && remainingProviders.length === 0) {
      setError(
        "Cannot disconnect your only sign-in method. " +
        "Please set a password or link another account first."
      );
      return;
    }

    const confirmed = window.confirm(
      `Are you sure you want to disconnect your ${provider} account?`
    );
    if (!confirmed) return;

    startTransition(async () => {
      const { error } = await authClient.unlinkAccount({
        providerId: provider,
      });

      if (error) {
        const resolved = resolveAuthError(error);
        setError(resolved.message);
      } else {
        setSuccessMsg(`${provider} account disconnected.`);
      }
    });
  };

  return (
    <div className="space-y-6">
      {/* Feedback */}
      {error && (
        <div role="alert" className="p-4 bg-red-50 text-red-700 rounded-lg border border-red-200">
          {error}
        </div>
      )}
      {successMsg && (
        <div role="status" className="p-4 bg-green-50 text-green-700 rounded-lg border border-green-200">
          {successMsg}
        </div>
      )}

      {/* Password Status */}
      <div className="p-4 border rounded-lg">
        <div className="flex items-center justify-between">
          <div>
            <p className="font-medium">Email & Password</p>
            <p className="text-sm text-gray-500">{user.email}</p>
          </div>
          <span className={`px-3 py-1 rounded-full text-sm ${
            hasPassword
              ? "bg-green-100 text-green-700"
              : "bg-gray-100 text-gray-600"
          }`}>
            {hasPassword ? "✓ Set" : "Not set"}
          </span>
        </div>
        {!hasPassword && (
          <a
            href="/account/set-password"
            className="mt-2 text-sm text-blue-600 hover:underline block"
          >
            → Set a password to protect your account
          </a>
        )}
      </div>

      {/* Social Providers */}
      <div>
        <h2 className="text-lg font-semibold mb-3">Connected Accounts</h2>
        <div className="space-y-3">
          {PROVIDERS.map(({ id, label, icon }) => {
            const isLinked = linkedProviders.includes(id);
            return (
              <div
                key={id}
                className="flex items-center justify-between p-4 border rounded-lg"
              >
                <div className="flex items-center gap-3">
                  <span className="text-xl">{icon}</span>
                  <div>
                    <p className="font-medium">{label}</p>
                    <p className="text-xs text-gray-500">
                      {isLinked ? "Connected" : "Not connected"}
                    </p>
                  </div>
                </div>
                {isLinked ? (
                  <button
                    onClick={() => handleDelink(id)}
                    disabled={isPending}
                    className="px-4 py-2 text-sm text-red-600 border border-red-300 rounded-lg hover:bg-red-50 disabled:opacity-50"
                  >
                    Disconnect
                  </button>
                ) : (
                  <button
                    onClick={() => handleLink(id)}
                    disabled={isPending}
                    className="px-4 py-2 text-sm text-blue-600 border border-blue-300 rounded-lg hover:bg-blue-50 disabled:opacity-50"
                  >
                    Connect
                  </button>
                )}
              </div>
            );
          })}
        </div>
      </div>

      {/* Active Sessions */}
      <SessionManager />
    </div>
  );
}
```

## Protected Server Actions

Always verify session at the top of every Server Action. Multi-factor authentication must be enforced at the API endpoint level, not just the UI.

```ts
// src/app/actions/profile.actions.ts
"use server";

import { requireAuth } from "@/lib/dal";
import { db } from "@/db";
import { user } from "@/db/schema/auth-schema";
import { eq } from "drizzle-orm";
import { z } from "zod";
import { revalidatePath } from "next/cache";

const UpdateProfileSchema = z.object({
  name: z.string().min(2, "Name must be at least 2 characters").max(50),
  image: z.string().url("Must be a valid URL").optional().or(z.literal("")),
});

export async function updateProfile(formData: FormData) {
  // ── 1. Always verify session first ───────────────────────────────────────
  const session = await requireAuth();

  // ── 2. Parse and validate input with Zod ─────────────────────────────────
  const parsed = UpdateProfileSchema.safeParse({
    name: formData.get("name"),
    image: formData.get("image") || undefined,
  });

  if (!parsed.success) {
    return {
      success: false,
      error: "Invalid input.",
      details: parsed.error.flatten().fieldErrors,
    };
  }

  // ── 3. Perform authorized operation ──────────────────────────────────────
  try {
    await db
      .update(user)
      .set({
        name: parsed.data.name,
        image: parsed.data.image ?? null,
        updatedAt: new Date(),
      })
      .where(eq(user.id, session.user.id));  // Always scope to session.user.id

    revalidatePath("/account");
    return { success: true };
  } catch (err) {
    console.error("[updateProfile]", err);
    return { success: false, error: "Failed to update profile. Try again." };
  }
}

export async function deleteAccount() {
  const session = await requireAuth();

  // Require fresh authentication before destructive actions
  // (redirect to re-auth page in practice)
  try {
    await db.delete(user).where(eq(user.id, session.user.id));
    return { success: true };
  } catch {
    return { success: false, error: "Could not delete account." };
  }
}
```

## Middleware (Routing Only)

> ⚠️ **Critical Security Note:** Middleware is no longer considered safe for authentication logic in Next.js. Use it **only for routing decisions**. All actual session verification must happen in the DAL via `requireAuth()`.

```ts
// src/middleware.ts
import { NextRequest, NextResponse } from "next/server";

// Routes accessible without authentication
const PUBLIC_PATHS = [
  "/",
  "/sign-in",
  "/sign-up",
  "/forgot-password",
  "/reset-password",
  "/verify-email",
  "/api/auth",
];

// Routes that authenticated users should be bounced away from
const AUTH_ONLY_PATHS = ["/sign-in", "/sign-up"];

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;
  const sessionCookie =
    request.cookies.get("better-auth.session_token")?.value ??
    request.cookies.get("__Secure-better-auth.session_token")?.value;

  const isPublic = PUBLIC_PATHS.some(
    (path) => pathname === path || pathname.startsWith(`${path}/`)
  );

  // Redirect already-authenticated users away from auth pages
  if (AUTH_ONLY_PATHS.some((p) => pathname.startsWith(p)) && sessionCookie) {
    return NextResponse.redirect(new URL("/dashboard", request.url));
  }

  // Do NOT block protected routes here — use DAL requireAuth() inside pages
  // This prevents middleware from becoming the auth gate (security anti-pattern)
  return NextResponse.next();
}

export const config = {
  matcher: [
    "/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)",
  ],
};
```

```ts
export function resolveAuthError(error: any): AuthErrorInfo {
  if (!error) {
    return { message: "An unexpected error occurred.", action: "retry" };
  }

  // Code-based lookup (most specific)
  if (error.code && AUTH_ERROR_MAP[error.code]) {
    return AUTH_ERROR_MAP[error.code];
  }

  // Status-based fallback
  switch (error.status) {
    case 400: return { message: "Invalid request. Check your input.",       action: "retry" };
    case 401: return AUTH_ERROR_MAP.SESSION_EXPIRED;
    case 403: return { message: "You don't have permission to do this.",    action: "contact_support" };
    case 404: return { message: "Resource not found.",                      action: "retry" };
    case 409: return { message: "A conflict occurred. Try a different method.", action: "retry" };
    case 429: return AUTH_ERROR_MAP.TOO_MANY_REQUESTS;
    case 500: return AUTH_ERROR_MAP.INTERNAL_SERVER_ERROR;
    default:  return { message: error.message ?? "An unexpected error occurred.", action: "retry" };
  }
}

// Error boundary hook for React components
export function useAuthErrorHandler() {
  return {
    handle: (error: any, setError: (msg: string | null) => void) => {
      if (!error) { setError(null); return; }
      const resolved = resolveAuthError(error);
      setError(resolved.message);

      // Auto-redirect for session issues
      if (resolved.action === "redirect_signin" && typeof window !== "undefined") {
        setTimeout(() => {
          window.location.href = "/sign-in?reason=session_expired";
        }, 2000);
      }
    },
  };
}
```

## Rate Limiting

Better Auth includes a built-in rate limiter to help manage traffic and prevent abuse. By default, in production mode, server-side requests made using `auth.api` aren't affected by rate limiting. Rate limits only apply to client-initiated requests.

Rate limiting is automatically applied to all Better Auth API endpoints. When a client exceeds the request limit, they receive a `429 Too Many Requests` response and must wait before retrying. These defaults balance security with usability.

Rate limits are applied across all routes by default, with specific routes subject to stricter limits based on potential risk. Better Auth uses client IP addresses for rate limiting and security monitoring.

```ts
// Rate limiting config inside betterAuth({...}) — expanded reference
rateLimit: {
  enabled: true,
  storage: "database",              // Persisted in Supabase via rateLimit table
  modelName: "rateLimit",
  window: 10,                       // Default window in seconds
  max: 100,                         // Default max requests per window

  customRules: {
    // Authentication endpoints — strictest limits
    "/sign-in/email":                   { window: 10,  max: 3  },
    "/sign-up/email":                   { window: 10,  max: 3  },
    "/forget-password":                 { window: 60,  max: 3  },
    "/reset-password":                  { window: 60,  max: 3  },

    // Passwordless flows
    "/sign-in/magic-link":              { window: 60,  max: 3  },
    "/email-otp/send-verification-otp": { window: 60,  max: 3  },

    // 2FA
    "/two-factor/verify-totp":          { window: 10,  max: 5  },
    "/two-factor/verify-backup-code":   { window: 60,  max: 5  },

    // Account management
    "/link-social-account":             { window: 30,  max: 5  },
    "/update-user":                     { window: 60,  max: 10 },
  },
},
```

> 💡 Most legitimate users won't hit these limits, but automated attacks will be blocked. Rate limiting is disabled in CI to prevent test flakiness. Never disable in production.

## Session Management

Better Auth uses secure session management to protect user data. Sessions are stored in the database or a secondary storage, if configured, to prevent unauthorized access. By default, sessions expire after 7 days, but you can customize this value in the configuration. Additionally, each time a session is used, if it reaches the `updateAge` threshold, the expiration date is extended, which by default is set to 1 day.

Better Auth allows you to revoke sessions to enhance security. When a session is revoked, the user is logged out and can no longer access the application. A logged-in user can also revoke their own sessions to log out from different devices or browsers.

Session timeouts define how long a user or API session can stay active before requiring reauthentication. Configuring them correctly isn't just about compliance; it's about balancing security, usability, and system performance across your tenants and auth flows.

```ts
// Session config reference inside betterAuth({...})
session: {
  expiresIn: 60 * 60 * 24 * 7,         // 7 days absolute TTL
  updateAge: 60 * 60 * 24,             // Extend if session is > 1 day old
  cookieCache: {
    enabled: true,
    maxAge: 5 * 60,                    // 5-min client-side cache (reduces DB hits)
  },
},
```

## Edge Case Hardening

| Attack / Scenario | Defense Mechanism |
|---|---|
| **Brute force password** | Rate limit: 3 req/10s per IP |
| **Email enumeration on sign-up** | `requireEmailVerification: true` makes sign-up response identical whether email exists or not |
| **User delinks only sign-in method** | Client-side guard + server-side: check `hasPassword && remainingProviders.length > 0` |
| **OAuth email-hijack via linking** | `allowDifferentEmails: false` prevents cross-email account takeover |
| **Social account already linked to another user** | `SOCIAL_ACCOUNT_ALREADY_LINKED` error caught and handled explicitly |
| **CSRF on form submissions** | Better Auth CSRF + origin header validation enabled by default |
| **Open redirect in callbackURL** | Better Auth validates `callbackURL` against `trustedOrigins` |
| **Multi-device abuse** | `multiSession` plugin with `maximumSessions: 5` cap |
| **Expired OAuth access token** | Better Auth auto-refreshes via `refreshToken` |
| **Session fixation** | New session token generated on every sign-in |
| **2FA bypass via pre-step token** | Some APIs issue a session token after step one of a two-step login before MFA is verified. If the server treats that token as fully authenticated, an attacker can call protected endpoints while bypassing the second factor entirely. Guard against this by only issuing a full session **after** 2FA completion. |
| **Credential stuffing** | 22% of all breaches begin with credential abuse. Defend with rate limiting, 2FA enforcement, and breach password checking. |
| **Server Action bypassed by direct POST** | Always call `requireAuth()` at the top of every Server Action |
| **Verification tokens leaked in logs** | `storeIdentifier: "hashed"` — tokens stored as hashes, never plain |
| **Server Actions with bad input** | Always validate with Zod before any DB operation |
| **Role escalation** | `requireAdmin()` checks `session.user.role === "admin"` server-side, never trust client-sent roles |
| **Account fragmentation (split identity)** | The same real person can unintentionally create multiple distinct Better Auth user accounts simply by using different emails during sign-in. Mitigate by enforcing `allowDifferentEmails: false` and educating users about linking. |
